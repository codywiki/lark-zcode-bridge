# /review 代码评审

## 触发条件
用户输入 `/review`，或要求评审 lark-channel-bridge-src 的代码改动时。

## 执行流程
1. 先用 `git diff` 或读取改动文件了解变更范围
2. 跑 `pnpm typecheck && pnpm test && pnpm build`
3. 用 LSP / grep 检查改动的影响面
4. 按清单逐项检查
5. 输出分类结论

## 检查清单

### 1. 正确性
- TypeScript 类型是否正确
- 消息转发、队列、批处理逻辑是否正确
- 流式卡片状态更新是否正确
- 会话生命周期（创建/恢复/中断）是否正确
- 命令解析（`/cd`、`/ws`、`/new`、`/stop`）是否正确

### 2. 测试覆盖
- 改动的核心逻辑是否有 unit 测试
- 改动的消息/卡片逻辑是否有 integration 测试
- 改动的子进程/隔离逻辑是否有 process 测试
- 是否破坏了现有测试

### 3. 性能
- 流式更新频率是否合理
- 大文件下载/上传是否流式处理
- 消息队列是否避免内存无限增长

### 4. 安全
- 是否暴露用户会话、token、本地路径
- 子进程启动是否受控
- 文件访问是否限制在允许范围内
- 命令中断/执行是否可能被滥用

### 5. 可维护性
- 错误处理与日志是否清晰
- 是否复用现有协议解析工具
- 是否新增 TODO/FIXME 并说明原因

## 输出格式

### 必须修（阻塞合并）
会导致类型错误、测试失败、会话异常、安全绕过或破坏消息协议的项。

### 建议修
不影响当前功能但会降低质量或未来返工的项。

### 无需修
已经合理或可以保留现状的项。

## 收尾
评审结束后，给出一句总体结论："当前改动可合并 / 需修复后重新评审 / 建议拆分"。
